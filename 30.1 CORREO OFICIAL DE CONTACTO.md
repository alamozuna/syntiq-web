# 30.1 CORREO OFICIAL DE CONTACTO

Todo lo relacionado con formularios de:

- Contacto
- Admisión
- Interés en talleres
- Lista de espera
- Formación individual
- Formación In-Company
- Solicitudes de información
- Mensajes generales desde la web

debe llegar al siguiente correo oficial de SyntIQ:

**syntiqgroup@gmail.com**

Este debe considerarse el correo receptor principal de los formularios públicos del sitio.

IMPORTANTE:

1. Revisa primero cómo funciona actualmente el formulario.

2. Si ya existe un sistema funcional de envío de emails, API route, server action, servicio SMTP, Resend, EmailJS, Formspree u otra integración:
   - conservar la arquitectura existente;
   - cambiar únicamente el destinatario cuando corresponda a:
     `syntiqgroup@gmail.com`

3. NO exponer credenciales, passwords, API keys ni secretos en el frontend.

4. Si el sistema requiere una variable de entorno para el destinatario, utilizar preferiblemente algo equivalente a:

   `CONTACT_EMAIL=syntiqgroup@gmail.com`

   y leerla únicamente desde el servidor cuando sea posible.

5. No hardcodear información sensible dentro de componentes client-side.

6. Verificar que los formularios de:
   - contacto individual;
   - interés en una formación;
   - lista de espera;
   - formación para empresas;

   envíen correctamente la información hacia ese correo.

7. El email recibido debe contener de forma estructurada:

   TIPO DE SOLICITUD

   Nombre

   Email

   Teléfono / WhatsApp, si fue proporcionado

   Formación seleccionada

   Modalidad:
   Individual / Empresa

   Empresa, si corresponde

   Tamaño del equipo, si corresponde

   Nivel actual, si corresponde

   Objetivo o mensaje

   Página/formación desde donde se originó el formulario

8. Utilizar asuntos claros.

Ejemplos:

`[SyntIQ] Nuevo interés — De Idea a App con IA`

`[SyntIQ] Nueva solicitud In-Company — Nombre Empresa`

`[SyntIQ] Nuevo contacto desde la web`

`[SyntIQ] Lista de interés — Arquitecto de Workflows`

9. Si el formulario recibe un parámetro como:

`?formacion=vibe-coding-idea-app`

incluir automáticamente esa formación tanto:

- en el formulario;
- como en el asunto;
- como en el contenido del correo recibido.

10. Después del envío mostrar el success state definido anteriormente.

11. Si el envío falla:

NO mostrar errores técnicos al usuario.

Mostrar:

“Hubo un problema al enviar tu solicitud. Inténtalo nuevamente o escríbenos a syntiqgroup@gmail.com.”

12. Mostrar también `syntiqgroup@gmail.com` en la página `/contacto` como método alternativo de contacto.

Debe aparecer de manera secundaria, por ejemplo:

“¿Prefieres escribirnos directamente?”

syntiqgroup@gmail.com

No debe competir visualmente con el formulario principal.

13. Convertir el correo visible en un enlace:

`mailto:syntiqgroup@gmail.com`

14. Verificar el envío completo de extremo a extremo.

No considerar el formulario terminado únicamente porque el frontend muestre un estado de éxito.

Confirmar que la solicitud realmente llega al destino configurado:

**syntiqgroup@gmail.com**
